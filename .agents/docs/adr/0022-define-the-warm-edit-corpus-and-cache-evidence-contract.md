# Define the warm-edit corpus and cache-evidence contract

Warm Compilation for the pinned IcedTasks Compatibility Corpus uses the exact line-count-preserving non-inline and public-inline edits, plus compiler-contact, replay, restore, failure-recovery, and fail-closed widening controls defined in the [issue #19 research](../research/warm-edit-corpus-and-cache-evidence-contract.md); only a real first post-edit `CoreCompile` contributes to the sub-second gate. Reuse is accepted only when a versioned trace proves complete input-key equality, separates exported, implementation, debug, and diagnostic fingerprints, reconciles causal per-node decisions and work counters, and produces the same artifacts as a clean standalone FSharp2 compile of those inputs. Unknown impact widens invalidation, failed requests preserve the last successful state and artifacts, the final link remains fresh, cache storage details stay private, and complete FS Diagnostic Compatibility remains mandatory at the final Compatibility Gate.
