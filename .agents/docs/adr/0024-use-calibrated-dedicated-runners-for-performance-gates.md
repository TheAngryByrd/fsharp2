# Use calibrated dedicated runners for performance gates

Authoritative FSharp2 performance gates run only on versioned, characterized, dedicated machine classes and compare an immutable accepted FSharp2 baseline with the candidate in same-machine, seed-balanced pairs; Compatibility Oracle timings remain context rather than the relative-regression baseline. `perf-governance-v1` requires audited quietness, power, processor, scanner, and indexer state, one untimed stabilization round, explicit compiler-state Cold controls, the ADR 0022 Warm edit protocol, 15 complete pairs within 18 scheduled pairs for controlled PR/nightly runs, and 30 within 36 for release. Every attempt and completed slow outlier is retained; candidate-owned correctness, state, timeout, output, or evidence failures fail immediately rather than becoming replaceable noise. Candidate gates remain Cold median `<= 3,000 ms`, Warm median `< 1,000 ms`, release Cold p95 `<= 3,000 ms`, release Warm p95 `< 1,000 ms`, and a relative median slowdown of both `>= 10%` and `>= 50 ms` whose paired-bootstrap interval is wholly slower.

Each valid timing row also retains a bounded uninstrumented phase/work summary and reconciled ADR 0022 causal work evidence. An invocation over three seconds itself emits the ADR 0016 MSBuild warning and structured trace covering phase timings, allocation/GC activity, cache decisions, input scale, and critical path; a heavier linked replay is additional and never joins the timing distribution. NativeAOT startup, daemon contact, an MSBuild skip, a complete-action hit, a silent whole-project miss, or wall time by itself does not prove Warm Compilation; the gate verifies stable semantic keys, source-order-safe narrow invalidation, and real compiler work while leaving all qualified processors available for proven-independent work. Hosted and ordinary local machines produce non-gating diagnostics, and machine, baseline, or policy changes require reviewed qualification and a new evidence lineage. Correctness, no-fallback proof, unchanged IcedTasks product inputs, and complete final-gate FS Diagnostic Compatibility remain prior. The exact machine schema, admission bounds, scanner controls, statistics, evidence profiles, verdicts, and promotion rules are defined by the [issue #12 research](../research/compiler-performance-runner-and-regression-governance.md).
