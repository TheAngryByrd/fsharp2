# Use the complete IcedTasks corpus for the first milestone

The first Experimental Vertical Milestone uses the complete IcedTasks Compatibility Corpus at commit `ba4e932b71bfde354f0e2561c2519b282fe56ff9` and tree `20abf5280d4630db438c7c6f06838105df12c765`, rather than the proposed five-file prefix or a synthetic fixture. Preserving the real `AutoOpens.fs` contract without IcedTasks-specific stubs or source changes requires all 17 authored library files, and the larger connected corpus proves the actual package boundary instead of a patched approximation.

## Compatibility envelope

- **Source and integration:** The four IcedTasks library inner builds are producer cases. Compatibility Oracle and FSharp2 producer lanes use the same hash-verified IcedTasks source, project, and ordered inputs and differ only in compiler selection. IcedTasks product source, projects, and tests remain unchanged. Controlled reversible source edits are permitted only as declared incremental-compilation inputs in isolated materializations; they are not IcedTasks product changes.
- **Compiler path:** Each supported FSharp2 compiler case traverses the real Release `CoreCompile` path for `netstandard2.0`, `netstandard2.1`, `net6.0`, or `net9.0`, including parsing, typechecking, requested optimization, emission, loading, and execution. Inputs outside this envelope fail explicitly before publishing successful output; production fallback to the official compiler remains forbidden.
- **Artifacts:** Every TFM must produce and validate the implementation DLL, portable PDB and SourceLink data, XML documentation, and reference DLL requested by the pinned project. The differential harness's metadata, F# metadata, determinism, downstream-consumption, and two NativeAOT gates remain mandatory.
- **Diagnostics:** Successful baseline and approved incremental cases are diagnostic-free under the project's warning-as-error policy. Two harness-owned negative probes require exact Compatibility Oracle behavior: `FS0010` for an unexpected `)` in a binding and `FS0001` for assigning a string expression to an `int`. The complete `FSxxxx` error-and-warning surface is mandatory at the final Compatibility Gate, not this milestone.
- **Consumers and runtime:** Keep the three existing `IcedTasks.Tests`, `IcedTasks.Tests.NS20`, and `IcedTasks.Tests.NS21` projects unchanged. Compile them with the Compatibility Oracle for every declared `net8.0`, `net9.0`, and `net10.0` target, separately against each producer lane's prebuilt library artifacts, and run every resulting test; their source and target frameworks are not FSharp2 compiler cases in this milestone. Separate harness-owned `net9.0` consumers run the mandatory Oracle/FSharp2 producer-consumer matrix and add runtime probes for the otherwise untested `taskUnit`, `backgroundTaskUnit`, and `valueTaskUnit` builders; `vTaskUnit` may share `valueTaskUnit` coverage as an alias. Combined evidence must exercise every distinct public builder family, including genuine suspension and resumption, cancellation, cold execution, background scheduling, and pooling where active.
- **Performance:** Time only real IcedTasks library Compiler Target Invocations. Cold Compilation bypasses live and disk compiler state; Warm Compilation retains valid state and compiles a declared changed input. The controlled-runner gates remain a cold median of at most 3,000 ms and a warm median below 1,000 ms. An unchanged target skip is not Warm Compilation.
- **Incremental evidence:** The warm lane must prove retained semantic work rather than only wall time. The edit corpus selected by [ADR 0022](0022-define-the-warm-edit-corpus-and-cache-evidence-contract.md) must include an implementation-only edit whose exported meaning is unchanged and a middle-of-order edit that changes consumer-visible meaning. Evidence identifies what was reused, rechecked, re-emitted, and transitively invalidated; uncertainty widens invalidation rather than risking stale output. This adopts the proof shape from the [comparative compiler research](../research/fast-fsharp-compiler-cold-and-incremental.md), with exact edits and cache evidence in the [issue #19 research](../research/warm-edit-corpus-and-cache-evidence-contract.md).

## Consequences

"First vertical slice" now means the smallest honest compatibility envelope around the unmodified real IcedTasks package, not the fewest source files. Diagnostics and unsupported-input fixtures live in the FSharp2 harness, and complete diagnostic expansion remains explicit Wayfinder work rather than being silently omitted or smuggled into this milestone.
