# Use DAP with a gated netcoredbg driver

The differential harness uses the Debug Adapter Protocol pinned to schema commit `e34479c39ed4973210115872c8e118c097a50d4a`. Its first redistributable managed-driver candidate is MIT-licensed Samsung `netcoredbg` release `3.2.0-1092`, source commit `9744e1f051866215611b8440c638042aa2aa2f72`, acquired only through reviewed length/SHA-256-pinned assets and a notice-complete offline mirror. A candidate asset is accepted per OS/RID/runtime cell only after an exact F# probe passes launch, attach, verified breakpoint binding, step-in/over/out, path-mapped source, locals, stack, async/task/computation-expression behavior, repeatability, and cleanup. A failed or missing driver probe is `infra-error` and blocks debugger comparison; it is never a FSharp2 failure, a pass, or omitted coverage.

The pinned release's documented F# computation-expression breakpoint defect, absent `sourceFileMap`/exact-source enforcement, and missing macOS x64, Windows Arm64, and musl assets remain explicit gates. The harness materializes the same hash-verified source at the mapped PDB path and independently verifies PDB document checksums. The final Compatibility Gate cannot claim a missing driver cell; it requires a reproducibly locked, notice-complete FSharp2-owned build or a reviewed replacement that passes the same probe. Proprietary `vsdbg` is excluded from authoritative standalone CI by its Microsoft-IDE-only license. Raw DAP correlation handles remain audit evidence while comparison uses a versioned semantic projection of breakpoints, stops, source ranges, frames, scopes, locals, exceptions, stepping, exit, and cleanup, as specified by the [issue #18 research](../research/cross-platform-debugger-automation-driver.md).

The driver and transcript are test-only and never enter the NativeAOT compiler graph, compiler service, cache schema, output, or MSBuild integration package. Debugger execution is post-compilation harness time, not a Compiler Target Invocation. This preserves the cold and incremental architecture from the [fast compiler research](../research/fast-fsharp-compiler-cold-and-incremental.md) while keeping Portable PDB/debug contributions within the symbolic emission boundary established by ADR 0021.
