# Use public SRM behind symbolic emission fragments

FSharp2 will own a versioned, immutable symbolic emission graph whose declaration and method fragments contain stable symbol identities, IL operands, labels, exception regions, and debug/resource contributions, but never final metadata handles, tokens, heap offsets, method offsets, RVAs, or PE/PDB identities. A fresh deterministic linker will plan final rows and layout, resolve those symbols, and use only the public .NET 10 `System.Reflection.Metadata`, `System.Reflection.Metadata.Ecma335`, and `System.Reflection.PortableExecutable` APIs, with narrow FSharp2-owned encoders for specification-defined gaps such as portable-PDB sequence-point/import/custom-debug blobs and managed/native resource layouts. This keeps the NativeAOT production closure static and the incremental cache independent of final row order or any serializer object model; alternative final encoders remain benchmark challengers behind the same symbolic boundary rather than defining it, as detailed in the [emitter research](../research/nativeaot-metadata-il-pdb-emitter-architecture.md).
